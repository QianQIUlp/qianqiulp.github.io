## 🧠 写在最前：先搞懂 SSH 的「方向」

<p>说实话，我自己一开始也以为 SSH 是「服务器之间的通讯协议」，每台机器都生成一对密钥放着就好。后来踩坑多了才意识到——<strong>这个模型对了一半，错了另一半</strong>。</p>

### 真正的模型：C/S，不对称

<p>SSH 走的是 <strong>客户端-服务器（C/S）模型</strong>，两端角色<strong>不对等</strong>：</p>
<ul>
  <li><strong>客户端</strong> = 发起连接的那一方（比如你的笔记本想 <code>git push</code>）</li>
  <li><strong>服务器</strong> = 被连接的那一方（比如 GitHub、云主机、跳板机）</li>
</ul>
<pre><code>[客户端 = 持私钥的发起方]  ──SSH──>  [服务器 = 存公钥的接收方]
    ↑                                    ↑
   私钥永不离开本机                  authorized_keys / GitHub 设置页</code></pre>

### 🎯 一句话口诀

<p>👉 <strong>谁发起连接，谁持有私钥；谁被连接，谁存对方的公钥。</strong></p>

### 🔗 由这个模型推导出的三条铁律

<ul>
  <li>🔹 <strong>密钥对的归属单位是「身份」，不是「机器类型」</strong><br>
  不是「每个服务器」要生成一对，而是「每一台<strong>会发起 SSH 连接</strong>的机器」要生成一对。笔记本一对、工作站一对、CI 节点一对；同一台机器也可以为不同身份建多对（个人 GitHub + 公司 GitHub）。</li>
  <li>🔹 <strong>私钥从生成到销毁，永远不离开本机</strong><br>
  不通过邮件、聊天、云盘、U 盘传播。要在新机器上「用同一个身份」？要么从加密的密码管理器（如 Bitwarden）恢复，要么直接在新机器上<strong>生成新密钥对</strong>、把新公钥重新挂到目标服务上。</li>
  <li>🔹 <strong>公钥可以随便公开，但必须放在「被连接方」</strong><br>
  在 GitHub，是网页里的 <code>Settings → SSH Keys</code>；在云主机，是 <code>~/.ssh/authorized_keys</code>。本质都是「服务器的白名单」。</li>
</ul>
<p>这一节是整篇教程的「为什么」。后面所有命令——为什么要 <code>chmod 600</code>、为什么要 <code>ssh-agent</code>、为什么 Windows 要多一行 <code>core.sshCommand</code>——回过头看都是在保护这个「私钥死守本机」的边界。</p>

## ① 准备私钥（二选一）

### 🟢 方案 A：从 Bitwarden 恢复旧密钥（换电脑首选）

<p>这是我每次换机走的路。理由很简单：<strong>保持同一个身份</strong>，GitHub 那边一行不用动。</p>
<ol>
  <li>打开 Bitwarden，找到对应条目（比如我自己的是 <code>SSH Key - GitHub (ed25519)</code>）</li>
  <li>复制私钥完整内容（<strong>含 <code>-----BEGIN ...-----</code> / <code>-----END ...-----</code> 行</strong>，少一行就废）</li>
  <li>把私钥写进本机：</li>
</ol>
<p>🪟 <strong>Windows</strong>（PowerShell）：</p>
<pre><code>New-Item -ItemType Directory -Force $env:USERPROFILE\.ssh | Out-Null
notepad $env:USERPROFILE\.ssh\id_ed25519</code></pre>
<p>🐧 <strong>Linux</strong>：</p>
<pre><code>mkdir -p ~/.ssh && chmod 700 ~/.ssh
nano ~/.ssh/id_ed25519
chmod 600 ~/.ssh/id_ed25519</code></pre>
<p>❗ <strong>Linux 上文件权限必须 600</strong>，否则 SSH 会以「权限过开」为由拒绝使用密钥。这是我第一次踩的坑——SSH 宁可让你登不上去，也不愿用一个全世界都能读的私钥。这个「过度保守」的设计其实是好事。</p>
<ol start="4">
  <li>（可选）从私钥反推公钥：</li>
</ol>
<p>🪟 <strong>Windows</strong>：</p>
<pre><code>ssh-keygen -y -f $env:USERPROFILE\.ssh\id_ed25519 > $env:USERPROFILE\.ssh\id_ed25519.pub</code></pre>
<p>🐧 <strong>Linux</strong>：</p>
<pre><code>ssh-keygen -y -f ~/.ssh/id_ed25519 > ~/.ssh/id_ed25519.pub</code></pre>
<p>（会要求输 passphrase——这就是 Bitwarden 里存的那个）</p>

### 🟡 方案 B：生成新密钥（换身份或全新设备）

<p>如果你想给新机器一个独立身份（推荐做法，特别是工作机），那就重新生成。两平台命令一致：</p>
<pre><code>ssh-keygen -t ed25519 -C "备注这个密钥对的信息"</code></pre>
<ul>
  <li>路径用默认 <code>~/.ssh/id_ed25519</code></li>
  <li>❗ <strong>必须设强 passphrase</strong><br>
  没 passphrase 的私钥 = 一个明文凭证。一旦本机被入侵或备份泄露，攻击者直接拿到你的 GitHub 身份。passphrase 给你一个「加密层」缓冲。</li>
  <li>生成完别忘了<strong>把新公钥贴到 GitHub</strong>（步骤 ⑤）和<strong>新建 Bitwarden 条目</strong>（最后的模板章节）</li>
</ul>

## ② 启动 ssh-agent（一次性配置）

<p>讲讲 <code>ssh-agent</code> 在这里扮演什么角色。</p>
<p>👉 <strong>ssh-agent 是一个常驻进程，负责「在内存里解密私钥并代为签名」。</strong></p>
<p>它存在的意义：</p>
<ul>
  <li>你输一次 passphrase，agent 把解密后的密钥握在内存里</li>
  <li>之后所有需要这个密钥的命令（<code>git push</code>、<code>ssh user@host</code>），都让 agent 在背后帮忙签名</li>
  <li>你不用每次都输一遍 passphrase</li>
</ul>
<p>本质是「<strong>用进程隔离，换便利性</strong>」——比把密钥裸放着安全，比每次手敲 passphrase 省心。</p>

### 🪟 Windows

<p><strong>管理员</strong> PowerShell：</p>
<pre><code>Set-Service ssh-agent -StartupType Automatic
Start-Service ssh-agent</code></pre>
<p>✅ 之后开机自启，<strong>永远不需要再跑</strong>。</p>
<p>验证：</p>
<pre><code>Get-Service ssh-agent</code></pre>
<p>看到 <code>Status: Running</code> 即可。</p>
<p>💡 <strong>Windows 版 ssh-agent 的关键差异</strong>：和 Linux 的进程级 agent 不同，Windows 这版是 <strong>系统服务 + DPAPI 持久化</strong>。<code>ssh-add</code>（或通过 <code>AddKeysToAgent yes</code> 在 <code>ssh</code> 解密成功后自动喂入）的密钥，会被 DPAPI 用你的 Windows 登录凭证加密后写入注册表 <code>HKCU\Software\OpenSSH\Agent\Keys</code>，<strong>重启后服务自启 → 自动从注册表恢复已加载的密钥</strong>。一次输 passphrase，长期托管。这是 Microsoft 移植版的特定行为，和 Linux 的「重启即清空」直觉不一样。</p>

### 🐧 Linux

#### 先判定场景（这一步决定后面的方案）

<p>🔹 <strong>桌面 Linux</strong>（GNOME / KDE / Ubuntu Desktop / Fedora Workstation）→ 多数情况 ssh-agent 已由桌面环境自动启动并集成 keychain</p>
<p>🔹 <strong>服务器 / 容器 / 跳板机</strong>（云 ECS、VPS、Docker、纯 SSH 登录的 Linux）→ <strong>没有</strong>自动 agent，需要手动配置</p>
<p>判定命令：</p>
<pre><code>echo $SSH_AUTH_SOCK</code></pre>
<ul>
  <li>有输出（一个 socket 路径） = 桌面，直接跳到步骤 ③</li>
  <li>空 = 服务器，往下看</li>
</ul>

#### 🟢 桌面 Linux

<p>桌面环境已经在帮你管 agent，<strong>通常什么都不用做</strong>。</p>
<p>首次 <code>ssh-add</code> 会弹图形界面问 passphrase，勾选「保存到 keychain」之后开机自动解锁。</p>

#### 🟢 服务器 / 非桌面 Linux —— per-SSH-session 推荐方案

<p>❗ <strong>先劝退一条路</strong>：不要走 <code>systemctl --user enable --now ssh-agent.service</code>：</p>
<p>🔹 多数发行版（Ubuntu 22.04 / 24.04、Debian 等）打包的 <code>ssh-agent.service</code> unit <strong>缺 <code>[Install]</code> 段</strong>，<code>enable</code> 直接报 <code>The unit files have no installation config</code></p>
<p>🔹 即便手写 unit 绕过，「agent 跟着开机时间常驻」对服务器是<strong>反模式</strong> —— 解密后的密钥长期驻留内存，且和「一次 SSH 登录 = 一次身份验证」的信任边界不对齐</p>
<p><strong>我选择的粒度</strong>：以「一次 SSH 登录」为生命周期。登入时拉一个 agent，登出时随会话自然清理。</p>
<p>这其实是把前面那条铁律「私钥死守本机」延伸到了内存层面——<strong>解密后的私钥也不该比会话活得更久</strong>。</p>

<h5>① 写入 <code>~/.bash_profile</code></h5>
<pre><code>cat > ~/.bash_profile <<'EOF'
# Source .bashrc for interactive shells (必须！否则丢 PS1 / alias / history 配置)
[ -f "$HOME/.bashrc" ] && . "$HOME/.bashrc"

# ssh-agent per SSH login session
SSH_ENV="$HOME/.ssh/agent-env"

start_agent() {
ssh-agent -s > "$SSH_ENV"
chmod 600 "$SSH_ENV"
. "$SSH_ENV" > /dev/null
}

if [ -f "$SSH_ENV" ]; then
. "$SSH_ENV" > /dev/null
kill -0 "$SSH_AGENT_PID" 2>/dev/null || start_agent
else
start_agent
fi
EOF</code></pre>
<p>❗ <strong>这是我踩过最阴的坑</strong>：Ubuntu 默认<strong>没有</strong> <code>.bash_profile</code>，登录 shell 走 <code>.profile</code> 间接 source <code>.bashrc</code>。一旦你自己建了 <code>.bash_profile</code>，bash <strong>只读它</strong>、不再读 <code>.profile</code> 也不读 <code>.bashrc</code>。所以<strong>第一行必须显式 source <code>.bashrc</code></strong>，否则会丢：</p>
<p>🔹 彩色 PS1（用户名/主机名变成默认白色）</p>
<p>🔹 所有 alias（<code>ll</code>、<code>la</code> 等）</p>
<p>🔹 history 去重、追加等配置</p>
<p>我第一次配完登进服务器，整个 prompt 变白，alias 全没——还以为系统坏了，折腾半小时才反应过来是 <code>.bash_profile</code> 屏蔽了 <code>.bashrc</code>。</p>

<h5>② 修改 <code>~/.bashrc</code>（兜底子 shell / tmux 重连）</h5>
<p>找到文件开头的 non-interactive guard：</p>
<pre><code>case $- in
*i*) ;;
  *) return;;
esac</code></pre>
<p><strong>紧接着</strong>插入一行：</p>
<pre><code>[ -f "$HOME/.ssh/agent-env" ] && . "$HOME/.ssh/agent-env" > /dev/null</code></pre>
<p>🔹 作用：tmux 跨 SSH 重连、或手动 <code>bash</code> 进子 shell 时，能从 <code>agent-env</code> 文件复用同一个 agent</p>
<p>🔹 位置必须在 guard <strong>之后</strong>，否则 <code>scp</code> 等非交互式调用也会执行，污染环境</p>

<h5>③ 配置 <code>~/.ssh/config</code></h5>
<pre><code>cat >> ~/.ssh/config <<'EOF'
Host *
AddKeysToAgent yes
IdentityFile ~/.ssh/id_ed25519
EOF
chmod 600 ~/.ssh/config</code></pre>
<p>🔹 <code>AddKeysToAgent yes</code>：<strong>首次用到密钥</strong>时自动加载进 agent，免手动 <code>ssh-add</code></p>
<p>🔹 第一次 <code>ssh -T git@github.com</code> 或 <code>git push</code> 输一次 passphrase，整个 SSH 会话内免输</p>

<h5>④ 退出并重新 SSH 登录</h5>
<pre><code>exit
# 在本地重新 ssh 进来</code></pre>
<p>⚠️ <strong>必须重新登录！</strong> 登录脚本只在登录那一刻读一次。在当前 shell <code>source ~/.bash_profile</code> 只能验证语法，<strong>不能完整模拟新登录会话</strong>。</p>

<h5>⑤ 验证</h5>
<pre><code>echo $SSH_AUTH_SOCK     # 应有值，类似 /tmp/ssh-XXXXXX/agent.1234
ssh-add -l              # "The agent has no identities."（agent 活着、还没密钥）
ssh -T git@github.com   # 第一次：输 passphrase → Hi &lt;user&gt;!
ssh -T git@github.com   # 第二次：直接 Hi &lt;user&gt;! 不再问</code></pre>

#### ⚖️ Linux 三种方案对比

<table>
  <thead><tr><th>方案</th><th>适用场景</th><th>优点</th><th>缺点</th></tr></thead>
  <tbody>
    <tr><td>桌面 keychain</td><td>GNOME/KDE 桌面</td><td>零配置、图形化解锁、开机持久</td><td>仅桌面环境</td></tr>
    <tr><td><strong>per-SSH-session（推荐）</strong></td><td><strong>服务器、容器、跳板机</strong></td><td>简单、信任边界清晰、无 systemd 依赖</td><td>每次 SSH 登录输一次 passphrase</td></tr>
    <tr><td>systemctl --user 常驻</td><td>极少数：每天反复 SSH 进出几十次、且不用 tmux</td><td>跨会话不重复输密码</td><td>需手写 unit、<code>enable-linger</code>、密钥长期驻留内存</td></tr>
  </tbody>
</table>
<p>🎯 <strong>我的选择规则</strong>：桌面用 keychain，服务器用 per-SSH-session，systemctl 路线只在极端高频场景才考虑。</p>

## ③ 把私钥加进 agent

<p>🪟 <strong>Windows</strong>：</p>
<pre><code>ssh-add $env:USERPROFILE\.ssh\id_ed25519</code></pre>
<p>🐧 <strong>Linux</strong>：</p>
<pre><code>ssh-add ~/.ssh/id_ed25519</code></pre>
<ul>
  <li>输入 passphrase（从 Bitwarden 复制）</li>
  <li>验证（两平台一致）：</li>
</ul>
<pre><code>ssh-add -l</code></pre>
<p>能看到指纹即成功。</p>
<p>🔹 Linux 桌面通常用 GNOME Keyring / KDE Wallet 集成，<strong>首次 <code>ssh-add</code> 会弹图形界面问 passphrase</strong>，可勾选「保存到 keychain」—— 之后开机自动解锁，<strong>无需每次 <code>ssh-add</code></strong>。</p>

## ④ 让 Git 走系统 OpenSSH

### 🪟 Windows（关键！）

<pre><code>git config --global core.sshCommand "C:/Windows/System32/OpenSSH/ssh.exe"</code></pre>
<p>🔹 没这一步，Git for Windows 会用<strong>自带的 MSYS ssh</strong>，那是一个独立的 ssh 实现，<strong>看不到 Windows 原生 ssh-agent 服务</strong>——结果就是 agent 明明在跑、密钥也加载了，<code>git push</code> 还是问你 passphrase。</p>
<p>🔹 这条配置是把 git 的 ssh 指针掰回到 Windows 自家的 OpenSSH 上。</p>
<p>这条我第一次没加，被反复问 passphrase 问到怀疑人生。</p>

### 🐧 Linux

<p>✅ <strong>不需要这一步</strong>。Linux 上 git 直接调用系统 <code>/usr/bin/ssh</code>，天然连接系统 ssh-agent。</p>

## ⑤ 把公钥贴到 GitHub

<p>这是「把公钥发给服务器」的具体操作——回想开头那条铁律：<strong>公钥放在被连接方</strong>。GitHub 在这里就是「被连接方」。</p>
<p>复制公钥到剪贴板：</p>
<p>🪟 <strong>Windows</strong>：</p>
<pre><code>Get-Content $env:USERPROFILE\.ssh\id_ed25519.pub | clip</code></pre>
<p>🐧 <strong>Linux（X11）</strong>：</p>
<pre><code>xclip -sel clip < ~/.ssh/id_ed25519.pub</code></pre>
<p>🐧 <strong>Linux（Wayland）</strong>：</p>
<pre><code>wl-copy < ~/.ssh/id_ed25519.pub</code></pre>
<p>🐧 <strong>Linux 兜底</strong>（直接显示再手动复制）：</p>
<pre><code>cat ~/.ssh/id_ed25519.pub</code></pre>
<p>去 GitHub → <code>Settings → SSH and GPG keys → New SSH key</code>，粘贴保存。</p>
<p>（从 Bitwarden 恢复的旧密钥，如果 GitHub 上已经有，<strong>跳过这一步</strong>——身份没变，对方白名单也不用动。）</p>

<p><strong>两平台一致</strong>：</p>
<pre><code>ssh -T git@github.com</code></pre>
<p>看到 <code>Hi &lt;你的GitHub用户名&gt;! You've successfully authenticated...</code> = ✅</p>
<p>任意 git 仓库里：</p>
<pre><code>git push</code></pre>
<p>不问 passphrase = 全链路打通。</p>

## ⚠️ 平台特殊情况

### 🪟 Windows：Git Bash 的 <code>ssh</code> 不连系统 agent

<p>Git Bash 里直接跑 <code>ssh -T git@github.com</code> <strong>会失败</strong> —— 它用的是 MSYS 自带 ssh，<strong>不连</strong> Windows ssh-agent。</p>
<p>🔹 <strong>不影响</strong> <code>git push</code>（因为已有 <code>core.sshCommand</code>）</p>
<p>🔹 如果非要在 Git Bash 里测，用完整路径：</p>
<pre><code>/c/Windows/System32/OpenSSH/ssh.exe -T git@github.com</code></pre>
<p>👉 平时测试只用 PowerShell 的 <code>ssh -T</code> 或任何地方的 <code>git push</code>。</p>

### 🐧 Linux：自动加载密钥

<p>想让 ssh-agent 在首次用到密钥时自动加载（少打一次 <code>ssh-add</code>），编辑 <code>~/.ssh/config</code>：</p>
<pre><code>Host *
AddKeysToAgent yes
IdentityFile ~/.ssh/id_ed25519</code></pre>
<p>之后第一次 <code>git push</code> 时弹一次 passphrase 输入，之后全免。</p>

## 📝 Bitwarden 条目模板

<p>建一条 <strong>Login</strong> 类型条目（<strong>不要</strong>用 SSH Key 类型——那是给 Bitwarden SSH Agent 功能用的，跟本指南方案不兼容）。</p>
<table>
  <thead><tr><th>字段</th><th>内容</th></tr></thead>
  <tbody>
    <tr><td>名称</td><td><code>SSH Key - GitHub (ed25519) - &lt;设备名&gt;</code></td></tr>
    <tr><td>用户名</td><td><code>id_ed25519</code></td></tr>
    <tr><td>密码</td><td><strong>passphrase 本体</strong></td></tr>
    <tr><td>附件 / Notes</td><td><strong>私钥完整内容</strong>（含 BEGIN/END 行）</td></tr>
  </tbody>
</table>

### Notes 字段建议写入（双平台恢复步骤）：

<pre><code>生成日期: YYYY-MM-DD
设备: &lt;Windows 笔记本 / Linux 工作站 / ...&gt;
邮箱: &lt;你的邮箱&gt;
算法: ed25519
公钥指纹: &lt;ssh-keygen -lf id_ed25519.pub 的输出&gt;
关联服务: GitHub (&lt;你的 GitHub 邮箱&gt;)

恢复步骤（Windows）:
1. 复制 passphrase 字段，先放剪贴板
2. 复制私钥到 C:\Users\&lt;你&gt;\.ssh\id_ed25519
3. PowerShell: ssh-add $env:USERPROFILE\.ssh\id_ed25519
4. git config --global core.sshCommand "C:/Windows/System32/OpenSSH/ssh.exe"
5. ssh -T git@github.com 验证

恢复步骤（Linux）:
1. 复制 passphrase 字段，先放剪贴板
2. mkdir -p ~/.ssh && chmod 700 ~/.ssh
3. 把私钥写入 ~/.ssh/id_ed25519，然后 chmod 600 ~/.ssh/id_ed25519
4. ssh-add ~/.ssh/id_ed25519
5. ssh -T git@github.com 验证</code></pre>

### ❗ 安全要点（跨平台一致）

<ul>
  <li>✅ 私钥<strong>必须带 passphrase</strong>（即 Bitwarden 密码字段非空）—— 否则 vault 一旦泄露，密钥裸奔</li>
  <li>✅ passphrase 和私钥<strong>存在同一条目</strong>（恢复时一一对应，不会错配）</li>
  <li>❌ 不要把<strong>未加密的明文私钥</strong>直接存进任何地方</li>
  <li>✅ 每生成一把新密钥 → <strong>新建条目</strong>，不要覆盖旧的（保留历史可追溯）</li>
  <li>✅ Bitwarden 主密码开 <strong>2FA</strong></li>
  <li>🐧 Linux 特别注意：<code>~/.ssh</code> 权限 700、私钥 600，否则 SSH 拒绝使用</li>
</ul>

## 🔄 日常使用

### 🪟 Windows

<p>✅ <strong>通常零操作</strong>。Windows ssh-agent 服务会把已加载的密钥用 DPAPI 加密后写入注册表 <code>HKCU\Software\OpenSSH\Agent\Keys</code>，开机自启后自动解密回 agent 内存——passphrase 已被「Windows 登录态」托管。</p>
<p>只有以下情况需要手动 <code>ssh-add</code> 一次：</p>
<ul>
  <li>🔹 首次配置、agent 里还没任何密钥（也可以靠 <code>AddKeysToAgent yes</code> 在第一次 <code>ssh host</code> 时自动喂入）</li>
  <li>🔹 主动 <code>ssh-add -D</code> 清空过 agent</li>
  <li>🔹 把 <code>ssh-agent</code> 服务设为 Manual / Disabled 后</li>
</ul>
<pre><code>ssh-add $env:USERPROFILE\.ssh\id_ed25519</code></pre>
<p>❗ <strong>安全含义</strong>：「能以你的 Windows 用户身份执行代码 = 能用你的私钥签名」。passphrase 在此模式下不再被询问，<strong>它实际上等价于你的 Windows 登录态</strong>。便利性 ↔ 本机被入侵时的爆炸半径，自行权衡。</p>

### 🐧 Linux

<ul>
  <li><strong>桌面环境（GNOME / KDE）+ keychain</strong>：✅ 完全零操作，开机自动解锁</li>
  <li><strong>服务器（按 per-SSH-session 配置完成）</strong>：✅ 每次新 SSH 登录时，第一次用到密钥（<code>ssh -T</code> 或 <code>git push</code>）会被问一次 passphrase，之后整个 SSH 会话免输；登出自动清理</li>
  <li><strong>未配 <code>AddKeysToAgent yes</code></strong>：每次 SSH 登录后手动 <code>ssh-add ~/.ssh/id_ed25519</code></li>
</ul>

  <thead><tr><th>现象</th><th>平台</th><th>检查 / 修复</th></tr></thead>

    <tr><td><code>Permissions ... are too open</code> 报错</td><td>🐧</td><td><code>chmod 700 ~/.ssh && chmod 600 ~/.ssh/id_ed25519</code></td></tr>

    <tr><td>GitHub 报 <code>Permission denied (publickey)</code></td><td>🪟🐧</td><td>公钥没贴 / 贴到了别的 GitHub 账号；重新复制贴一次</td></tr>

## 🎯 压缩流程（换电脑速查）

<p>如果你只是回来翻速查表，看这一节就够了。</p>

### 🪟 Windows

<p>👉 <strong>5 步走</strong>：</p>
<p>① 管理员 PowerShell：<code>Set-Service ssh-agent -StartupType Automatic</code> + <code>Start-Service ssh-agent</code></p>
<p>② 从 Bitwarden 恢复 <code>id_ed25519</code> 到 <code>~/.ssh/</code></p>
<p>③ <code>ssh-add $env:USERPROFILE\.ssh\id_ed25519</code>（输 passphrase）—— 或在 <code>~/.ssh/config</code> 写 <code>AddKeysToAgent yes</code>，第一次 <code>ssh host</code> 时自动喂入</p>
<p>④ <code>git config --global core.sshCommand "C:/Windows/System32/OpenSSH/ssh.exe"</code></p>
<p>⑤ <code>ssh -T git@github.com</code> 或 <code>git push</code> 验证</p>
<p>✅ 之后重启<strong>不需要</strong>重复任何步骤 —— 密钥已被 DPAPI 持久化到注册表，agent 服务自启时自动加载</p>

### 🐧 Linux 服务器（per-SSH-session）

<p>👉 <strong>5 步走</strong>：</p>
<p>① 从 Bitwarden 恢复 <code>id_ed25519</code> 到 <code>~/.ssh/</code>，<code>chmod 700 ~/.ssh</code> + <code>chmod 600 ~/.ssh/id_ed25519</code></p>
<p>② <code>start_agent</code> 块写进 <code>~/.bash_profile</code>（<strong>第一行必须 source <code>.bashrc</code></strong> 否则丢 PS1 和 alias）</p>
<p>③ <code>~/.bashrc</code> 的 non-interactive guard 后插入 <code>[ -f "$HOME/.ssh/agent-env" ] && . "$HOME/.ssh/agent-env" > /dev/null</code></p>
<p>④ <code>~/.ssh/config</code> 加 <code>Host *</code> + <code>AddKeysToAgent yes</code> + <code>IdentityFile ~/.ssh/id_ed25519</code></p>
<p>⑤ <code>exit</code> 重新 SSH 登入 → <code>ssh -T git@github.com</code> 输一次 passphrase 验证</p>

### 🐧 Linux 桌面

<p>👉 <strong>3 步走</strong>：</p>
<p>① 从 Bitwarden 恢复 <code>id_ed25519</code> 到 <code>~/.ssh/</code>（<code>chmod 600</code>）</p>
<p>② <code>ssh-add ~/.ssh/id_ed25519</code>（图形界面输 passphrase，勾选保存到 keychain）</p>
<p>③ <code>ssh -T git@github.com</code> 验证</p>

## 🧭 最后的心智模型

<p>所有这些操作，回头看其实只在反复贯彻同一件事：</p>
<p>👉 <strong>谁发起连接，谁持有私钥；谁被连接，谁存对方的公钥。私钥从生成到销毁，永不离开本机内存或加密存储之外的任何介质。</strong></p>
<ul>
  <li>🔹 <code>chmod 600</code> 是在保护<strong>文件层</strong></li>
  <li>🔹 <code>passphrase</code> 是在保护<strong>存储层</strong></li>
  <li>🔹 <code>ssh-agent</code> 是在控制<strong>内存层</strong>的解密窗口</li>
  <li>🔹 <code>core.sshCommand</code> 是在保证<strong>调用链</strong>没走偏</li>
  <li>🔹 Bitwarden 是在解决<strong>跨设备恢复</strong></li>
</ul>
<p>🎯 <strong>跨平台决策规则</strong>：私钥永远带 passphrase；passphrase 永远存 Bitwarden；日常用系统 ssh-agent；Windows 多一步 <code>core.sshCommand</code>，Linux 多注意文件权限。</p>
